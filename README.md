# Портал за прозрачност на Община Лом

Уеб платформа с отворени данни за бюджета, разходите, обществените поръчки,
решенията на Общинския съвет, наредбите и администрацията на Община Лом.
Данните идват от ръчно въведено съдържание през административния панел и от
автоматизирано извличане (scraping) на публикуваната информация на lom.bg,
преминаващо през ръчен преглед и одобрение преди публикуване.

## Структура на проекта

```
lom-transparency/
├── server/              # Express бекенд + SQLite база данни
│   ├── db/               # Схема и модулни разширения на схемата
│   ├── middleware/        # Автентикация, качване на файлове
│   ├── routes/            # API маршрути + модулни разширения
│   ├── scraper/           # Клиент и модули за извличане на данни от lom.bg
│   └── tests/              # node:test + supertest
├── public/              # Статични страници (публичен сайт + администрация)
├── tests/                # Playwright end-to-end тестове
└── .github/workflows/    # CI (тестове) и седмичен job за синхронизация
```

Виж [ARCHITECTURE.md](./ARCHITECTURE.md) за обяснение на архитектурата,
включително механизма за автоматично зареждане на модули ("auto-mount
registry"), който позволява паралелна разработка на функционалните модули
без конфликти в общи файлове.

Виж [SECURITY.md](./SECURITY.md) за модела на сигурност и [CHANGELOG.md](./CHANGELOG.md)
за история на промените.

## Инсталация и стартиране

### Изисквания

- Node.js 20+
- npm

### Бекенд сървър

```bash
cd server
npm install
npm start
```

Сървърът стартира по подразбиране на порт `3000` (може да се промени чрез
променливата на средата `PORT`). При първо стартиране се създава SQLite база
данни (`server/lom.db` по подразбиране, конфигурируема чрез `LOM_DB_PATH`) и
се засява единствен администраторски акаунт:

- потребителско име: `admin` (или стойността на `LOM_ADMIN_USERNAME`)
- парола: `admin123` (или стойността на `LOM_ADMIN_PASSWORD`)

**Задължително променете паролата на администратора преди реално
разгръщане**, като зададете `LOM_ADMIN_PASSWORD` преди първото стартиране.

Публичният сайт и административният панел се обслужват от същия сървър:

- Публичен сайт: `http://localhost:3000/`
- Администрация: `http://localhost:3000/admin/index.html`

### Извличане на данни от lom.bg (scraping)

```bash
cd server
npm run sync
```

Изпълнява всички регистрирани модули в `server/scraper/modules/`. Резултатите
от извличането се записват със статус `pending` и трябва да бъдат одобрени
от администратор през панела за преглед, преди да се появят на публичния
сайт.

**Забележка за модул `minfin`**: за разлика от останалите модули,
`server/scraper/modules/minfin.js` тегли данни от minfin.bg през `patchright`
(headed Chromium — виж коментара в началото на файла защо е нужен headed
браузър вместо plain HTTP fetch, заради Cloudflare защита). Заради това
`npm run sync` за този модул изисква интерактивна десктоп сесия (не работи
на headless CI/сървър без display) — останалите пет модула нямат това
ограничение.

### Тестове

Тестове на бекенда (Node.js test runner + supertest):

```bash
cd server
npm test
```

End-to-end тестове (Playwright, изпълняват се от корена на проекта и сами
стартират сървъра):

```bash
npm install
npm test
```

Полезни варианти: `npm run test:ui` (UI режим), `npm run test:headed`
(с видим браузър), `npm run test:report` (отваря последния HTML отчет).

## Модули

Шест функционални модула на портала са изградени: бюджет и разходи,
обществени поръчки, решения на Общинския съвет, наредби, администрация и
финансови показатели на общините (Министерство на финансите). Всеки има
собствена схема (`server/db/modules/`), API маршрути
(`server/routes/modules/`), скрейпър модул (`server/scraper/modules/`,
където е приложимо), публични страници (`public/<модул>/`) и
административен панел (`public/admin/<модул>.html`). Началната страница
(`public/index.html`) обобщава показатели от първите пет модула (финансовите
показатели на МФ имат собствена връзка в навигацията, но не и плочка на
началната страница), а "Бюджет" и "Обществени поръчки" са кръстосано
свързани там, където дадена поръчка е обвързана с конкретен бюджетен
проект.

За какво точно покрива всеки модул, откъде идват реалните му данни от
lom.bg и какви честно установени ограничения има всеки източник (напр.
слабото "Профил на купувача" на lom.bg за обществени поръчки — покрито
вместо това през e-obp.eu, и оскъдния контактен указател на lom.bg за
администрацията) — вижте раздел "Функционални модули" в
[ARCHITECTURE.md](./ARCHITECTURE.md).

## Принос към проекта

Проектът е проектиран за паралелна разработка на функционалните модули от
отделни агенти/екипи, чрез добавяне на файлове в `server/db/modules/`,
`server/routes/modules/` и `server/scraper/modules/` — без да се налага
промяна на споделените базови файлове. Подробности в
[ARCHITECTURE.md](./ARCHITECTURE.md).
